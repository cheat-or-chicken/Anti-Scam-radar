# Anti-Scam Radar 技術圖解

這份 5 頁 PowerPoint 可直接插入主簡報。流程節點、文字、連線都是可編輯物件，框架 logo 為獨立 SVG 圖片；同名順序 PNG 適合貼到其他簡報工具。內容依本工作目錄的實際程式核對，包含尚未提交的聊天室修改。

## 建議講法

1. **整體流程**：瀏覽器先做本機檢查，再由後端取得可用證據。LLM 分析程式碼、內容及畫面，最後比較整體情境。程式驗證介入條件，前端列出所有問題。
2. **檢查分工**：L0–L17 是有明確輸入、輸出的驗證入口。每層保留缺資料與錯誤狀態，避免把無法查核當作安全。其他 API 並非每次分析都自動執行。
3. **自適應**：日常情境判斷、deep 模式補查、離線規則改善是三種能力。最適合強調的創新是比較正常與詐騙解釋，提出反證及改判條件，再按目前情境調整提醒。
4. **聊天室**：網址查核與對話判斷並行，各自回報。警告在敏感要求提出時出現，重播會停下來。下一步預測必須等新訊息才能驗證。
5. **技術架構**：Chrome MV3 與原生 JavaScript 前端，FastAPI 網站 API、Python 標準庫聊天室 API，共用驗證模組。外部 Responses API 負責 LLM，本機 SQLite 與 JSONL 負責追溯。

## 上台時需要保留的界線

- 一般 extension 分析執行固定適用檢查，LLM 不自由省略這些檢查。深度工具規劃只在 CLI deep 模式啟用。
- `workflow.py` 的未知事項、改判條件是分析結果，不會自動觸發補查工具。圖中的三種自適應不是已串好的自動學習閉環。
- `diagnose` 產生改善候選，`adaptive.py` 產生有限 DSL 規則並提供測試／核准入口。目前没有定期排程、候選自動部署或模型訓練。
- DSL 核准門檻為至少 15 正例與 15 反例、零誤報、召回率至少 0.5，且需人工核准。這是程式門檻，不能當成真實世界準確率。
- `/v1/verify-brand`、`/v1/analyze-semantics`、`/v1/indicators` 已有獨立 API，但目前 extension 的標準 `/v1/analyze` 不會呼叫這三個入口。
- 聊天室 URL 查核結果與對話結果共用介面，目前未把 URL 結果送進對話 LLM。
- L7 是靜態 JS 審查。選用 `capture.py` 的 Playwright 頁面擷取會載入真實頁面，不能把整個專案描述成完全不執行 JS。
- 已有的前後端遮罩處理文字，沒有保證截圖中的個資被 OCR 遮罩。截圖由使用者選擇是否啟用。
- 一般瀏覽器 DOM 快照不能證明錢流向何處或已外傳資料。聊天室的「已送出」也是使用者回報。
- logo 表示使用的技術或服務，不代表合作或官方背書。

## script 全檔案對照

| 檔案／模組 | 流程中的角色 |
|---|---|
| `__init__.py`、`layers/__init__.py` | 套件入口與驗證 function registry |
| `config.py`、`models.py` | 設定、預算、API key 與型別／資料邊界 |
| `cli.py` | analyze、layer、tool、extract、replay 等命令入口 |
| `server.py` | FastAPI 橋接與驗證／診斷 API |
| `extract.py`、`domains.py` | HTML 解析、URL 正規化與註冊網域邊界 |
| `capture.py` | 選用 Playwright 頁面與截圖擷取 |
| `images.py`、`vision.py` | 本機 QR／OCR 與 LLM 截圖辨識 |
| `privacy.py`、`data/privacy_patterns.json` | LLM 文字輸入遮罩，與前端共用模式 |
| `pipeline.py` | 各層、外部證據、LLM、裁決與稽核的主流程 |
| `layers/rules.py` | L0–L16 規則；L7 同步入口為待審查占位 |
| `layers/code_review.py` | L7 真正的 LLM 靜態 code review |
| `layers/adjudication.py` | 分數去重、硬證據限制、L17 與介入門檻 |
| `llm.py` | Responses API 共用封裝、schema、預算、遮罩及語意補充 |
| `workflow.py` | 意圖、假設、證據、改判條件、介入政策與錯判診斷 |
| `investigation.py` | deep 模式受限 function calling 迴圈 |
| `tools.py`、`network.py` | 工具白名單、限額與 SafeFetcher 公網擷取 |
| `google_reputation.py` | Google URL 信譽查詢 |
| `blocklist.py`、`build_blocklist.py` | 人工確認名單判斷與名單建置 |
| `brand_patterns.py`、`semantic_rules.py` | 品牌相似模式及可維護的語意規則 |
| `site_checks.py` | 獨立品牌官方來源查證、語意分析 API 實作 |
| `indicators.py` | 補充網站與網域指標查核 |
| `storage.py` | SQLite 稽核、文字指紋、回報、replay |
| `adaptive.py` | 有限 DSL 候選、shadow 評估與人工核准 |
| `evaluate.py`、`smoke_site_checks.py` | 固定案例評估與網站 API smoke 測試 |
| `progress.py` | 分層進度與事件紀錄 |
| `demo_server.py` | 詐騙情境 demo 網站服務 |
| `package_extension.py` | extension 發佈封裝輔助 |
| `data/brands.json`、`blocklist.json`、`semantic_rules.json`、`risk_messages.json` | 品牌／黑名單／話術規則／白話提醒資料 |

另外：`extension/src` 負責採集、短期跨頁摘要與互動提醒；`ChatRoom` 負責對話規則、下一步預測／核對、URL 卡片與重播；`tests` 與 extension 瀏覽器測試驗證行為。這些測試不能直接換算成偵測準確率。
