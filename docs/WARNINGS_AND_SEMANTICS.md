# 警示顯示與話術辨識補強

## 警示顯示

原本 35 分以下只顯示 icon，LLM 的低權重訊號可能存在但沒有頁面提示；content script 又以單一 dismissed 布林值記住關閉狀態，使後續新警訊一起被略過。本次依使用者要求改成：

- 只要有正風險分，就顯示 banner、工具列標記與一致的 popup 提示。低權重不直接升為硬封鎖；原有多層／硬證據封鎖條件保留。維護的可信網域如有訊號，也顯示 banner。
- 關閉狀態限定同一網址與同一組訊號／權重。單純重掃或更新時間不重複打擾，但新增證據或換頁會重新提醒。
- 新風險會重設頁面內的臨時操作放行。使用者在全頁警示上明確選擇的五分鐘放行仍按原規則運作。
- 網頁移除 overlay DOM 時，會節流嘗試重建；更舊的非同步結果不覆蓋新結果。瀏覽器內部頁、未啟用擴充功能或明確關閉／放行，仍不應被當成警示失效。

`extension/src/warning_state.js` 提供可測試的警示識別與顯示條件；`src/content.js` 處理重現與關閉；Python／JS 裁決與 popup／badge 已同步。

## 白話提示

`script/data/risk_messages.json` 為 Python 與 JS 共用文案。採「哪裡可疑 → 正常情況 → 建議動作」表達：

- 品牌：頁面提到誰、目前網址不屬於已核對的官方域名、提供維護過的官方網址並提醒自行查詢。
- OTP：正常登入是你在確認過的官方頁面輸入，客服不需要代收驗證碼。
- 遠端客服：查訂單不需要讓陌生人控制裝置，改從官方管道聯絡。
- 假中毒：網頁警告不是系統掃毒結果，先從裝置既有的安全設定檢查。
- 假驗證：真人驗證不需要 Win+R、貼上並執行指令。
- 提領／領獎：要求先付款才領到資金，應停止付款並獨立查證。

## 話術與 LLM

`script/data/semantic_rules.json`、`script/semantic_rules.py` 共用條件組合，增加假中毒催促操作、假驗證要求執行指令、先付費提領／領獎。規則要求同句多個要素，不因提到病毒或 CAPTCHA 就直接加分，並排除常見教育／否定用語。

另增加交易平台標題 + 多倍成長 + 高可靠性數字的低權重待查證訊號，支援中、英、德語表達。不是「保證收益」判定，也沒有查明公司犯罪或牌照失效；一般新聞標題、一般軟體頁面不因引述同樣數字命中此組合。

`SEMANTIC_GUIDANCE` 由自動 L3 與独立語意 API 共用；L3 現在連同標題分析，補上非 OTP 的 reason_code，且保留新聞、教育、正常流程及證據不足的區分。模型結果仍是 inferred，只加弱訊號；不執行 JS、不以未知 URL 或使用者懷疑直接判定詐騙。

## 使用者案例與測試

原始 `fisios2-impedit71.sbs` 的完整入口本次 HTTP 抓取為 404，未推定其現在的內容。後續提供的 [Selqorun Vexalith](https://selqorunvexalith.com/) 可讀，標題是 AI 交易平台，正文含多倍成長與可靠性數字；本次抓取快照經新規則得到 20 分 banner、分類「話術詐騙疑慮」。另以真實 OpenAI 呼叫自動 L3 與獨立語意 API，各一次，均標示 `unsubstantiated_trading_claims`，不是已確認詐騙。原文／模型輸出僅存 `var/`，不提交完整網址追蹤參數或頁面私人資料。

`tests/test_social_engineering.py`、`extension/tests/warnings.test.js` 包含正／負例、三語言组合、新聞對照、低分提示與關閉識別。`extension/tests/demo.mjs` 另以真實 Chrome 檢查低分顯示、手動關閉後同一警訊不重複、新增風險重現、網頁移除提示後重建。

實際瀏覽器回歸另外重現兩個時序問題並修正：

- 導覽初始化可能比 content snapshot 晚寫入，將已完成檢查蓋成 0 分。background 現在按分頁序列化狀態寫入，初始化不覆蓋同 document 的完整快照。
- DOM 變更已排程，但中途強制重掃更新了節流時間，原定時器觸發時會直接丟掉變更。現在節流期間遇到新內容會重新排程，保留最後一次變更直到完成掃描。

本次 Python 158 項、Node 17 項通過；一般 Chromium 整合通過。新低分／關閉／恢復情境也以獨立 profile 實測。兩次真實 LLM 呼叫使用公開抓取快照，未拿教學頁的預設期待當模型輸入指令。
